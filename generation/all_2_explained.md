## generator.py (writer node)
- This node has two different works related to generating response.
    - One: generate response normally
    - Two: in case of the response gets `fail`, consider that `feedback` provided by the `reviewer node` and regenerate the response.
        - small note: as per the project architecture, even if the second response gets failed, similarly with the 4 more response get failed, no matter what the 6th response gets, its considered as final response. all the information is mentioned in the `readme` and `project_explainnation` md files 
- This node takes the retrieved_results (context) from any two of retrieval methods and generates a response which looks far better than raw llm output, as the prompt is designed in such way.
- The prompt used in this script will, add emojis to the response, make that response look professional and also like making a notes of it.

## reviewer.py

This node is the first needed thing for the concept `agentic reflection loop`.

This node reviews the response generated by the writer node, analyzes it and tries to find any missing points or wrong framing if there are any, and if it finds any of them it generates a `feedback`, which is sent to the writer node again in the next iteration, so that it can generate the response again.

### code breakdown

```python
from pydantic import BaseModel, Field
from typing import Literal, Optional
from router.query_router import client

class ReviewSchema(BaseModel):
    status: Literal["pass", "fail"]
    feedback: Optional[str] = Field(
        default="",
        description="Detailed feedback if status is 'fail'. Specify what is missing or incorrect. If status is 'pass', return an empty string ''."
    )
```
- We define a **Pydantic schema** called `ReviewSchema` to force the LLM to return a structured output.
- It contains two fields:
  - `status`: Which can only be `"pass"` or `"fail"` (enforced using `Literal`).
  - `feedback`: An optional string (`Optional[str]`) that gets filled with detailed critique only if the status is `"fail"`. We use `Optional[str]` with a default of `""` so that if the LLM returns `null` or nothing when the answer passes, it doesn't crash our JSON parser.
- We reuse the same `client` instance (which connects to the Groq/Llama model) to run this evaluation.

```python
async def review_answer(query: str, answer: str, retrieval_results: list[dict]) -> dict:
    contexts = [res["context"] for res in retrieval_results]
    merged_context = "\n\n".join(contexts)
```
- The function takes:
  - `query`: The user's original question.
  - `answer`: The response generated by the writer node.
  - `retrieval_results`: The list of contexts retrieved from the vector store or internet.
- Just like in the generator node, we merge all the retrieved contexts into a single string (`merged_context`) so the reviewer can check the facts.

```python
    prompt = f"""
    You are the Reviewer Node of a Hybrid GraphRAG system.
    ...
    Return a JSON object with keys 'status' and 'feedback'.

    structured_llm = client.with_structured_output(ReviewSchema, method="json_mode")

```
- We write a system prompt instruction sheet for the LLM to act as a strict Reviewer. It checks two things: **Relevance** (answering the question) and **Factuality** (avoiding hallucinations).
- We use `.with_structured_output(ReviewSchema, method="json_mode")` to compile a schema-based output router.
- We invoke the LLM asynchronously with `ainvoke(prompt)`.

```python
    # Print the evaluation status directly to the terminal logs
    print(f"\n--- [REVIEWER NODE] Evaluation Status: {response.status.upper()} ---")
    if response.status == "fail":
        print(f"Feedback: {response.feedback or ''}\n")

```
- We print the reviewer node's evaluation status directly to the terminal console so we can see the reflection loop in action.
- Finally, we return the status and clean feedback to the graph. Let's explain the line `'feedback': (response.feedback or "") if response.status == "fail" else ""` step-by-step:
  - **The Condition (`if response.status == "fail" else ""`)**:
    - If status is `"pass"`, it immediately goes to `else ""` and returns an empty string `""` because no feedback is needed.
    - If status is `"fail"`, it evaluates the left side: `(response.feedback or "")`.
  - **The Safety Net (`response.feedback or ""`)**:
    - If `response.feedback` has a text critique like `"Missing details"`, Python returns that text.
    - If `response.feedback` is `None` (JSON `null`), Python treats `None` as falsy and falls back to `""` (empty string).
  - This ensures our state's feedback key is always a clean string (`str`) and never `None`, avoiding any Pydantic schema validation errors.
