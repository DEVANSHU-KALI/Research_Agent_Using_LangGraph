# Explanation of Backend and Frontend Scripts

This file contains the detailed explanation for `main.py` (FastAPI backend) and `app.py` (Streamlit frontend), focusing specifically on real-time token streaming and reflection monitoring.

---

## 1. What these Scripts Do & Why they are Needed
In a standard RAG system, the user submits a question and wait. Because our system includes a **self-reflection loop** (where the answer can be rewritten up to 5 times), this wait time can easily exceed 10 to 15 seconds. If the UI is static, the user might assume the system has crashed.

To solve this:
- **`main.py` (Backend)**: Exposes a `/stream` API endpoint. Instead of waiting for the graph to finish, it taps into LangGraph's internal events and streams LLM tokens to the client as they are generated.
- **`app.py` (Frontend)**: Connects to the backend via a streaming HTTP request. It consumes the incoming text stream and displays it typewriter-style in real time.

---

## 2. Core Concept: LangGraph Events (`astream_events`)

### What are Events?
When you call `graph.astream_events(..., version="v2")`, LangGraph runs the state machine asynchronously and outputs a stream of structured events representing every internal operation. These events detail:
- When a node begins (`on_node_start`) or completes (`on_node_end`).
- When a chat model starts (`on_chat_model_start`) or outputs a token (`on_chat_model_stream`).

### Why do we need events here?
We need them to extract two things in real time:
1. **Tokens**: The individual characters/words generated by the LLM.
2. **State Updates**: The metadata, such as the loop iteration count, when the writer node finishes running.

### Why filter by specific event types and nodes?
If we streamed *every* event, the user's chat screen would print the Supervisor routing decisions (`"semantic"`, `"internet"`) and the Reviewer's feedback critiques! 

To prevent this:
- We check `event.get("event") == "on_chat_model_stream"` to only extract token chunks.
- We check `metadata.get("langgraph_node") == "Writer"` to ensure we **only** stream tokens from the **Writer** node, ignoring the Supervisor and Reviewer LLM outputs.
- We check `event.get("event") == "on_node_end"` for the `"Writer"` node to capture the updated state variables like `iteration_count`.
